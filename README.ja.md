# Auto Make Timeline 1.0.0.3

Dalamud API15 / Windows x64 / .NET 10 向けの戦闘タイムライン記録プラグイン。

## 検証状況

AMTのReleaseビルド成功（警告0・エラー0）、自動テスト165項目合格。今回の更新対象はAMTのみで、devLibraのソース・DLL・配布ZIPは変更していません。
実ゲーム内でのロード・攻撃受信・画面表示は未検証です。
このパッケージは実機評価用のビルド済み資材であり、実機確認を完了した正式リリースではありません。
Dalamud公式リポジトリへの登録・審査・公開は行っていません。

## 敵ステータス・ダメージ分析の追加（1.0.0.3のまま）

- **敵バフ／敵デバフ**：各攻撃元のステータスを攻撃受信時に保存し、アイコン＋名称で表示します。敵側は攻撃力アップ等も表示します。取得できない攻撃元や旧履歴は「取得不可」です。
- **味方バフ**：被ダメージ軽減・バリア効果に限定します。攻撃力アップ、回復力アップだけの効果、食事、カンパニーアクションは表示しません。味方デバフは引き続き表示します。Statusシートの説明文から作ったID分類を使用します。ゲーム更新で追加・変更された効果は分類の更新が必要になる場合があります。
- **同一No.内の降順**：被ダメージの大きい順。同値は元の順序、ダメージなしは末尾です。異なるNo.の時系列は維持します。画面と確定／再出力CSVで共通です。
- **残りHP／致死色**：EffectResult／EffectResultBasicの攻撃シーケンスと対象IDを照合して、サーバー更新のHPを保存します。HPが0で被弾前に生存し、正のダメージがある行のダメージを赤くします。HP更新未受信、DoT、旧履歴は「取得不可」で、推測で赤色にしません。CSVは色の代わりに「致死」列を持ちます。更新照合は受信後15秒以内です。
- **列順変更**：「列変更：ロック中」を押して「許可中」にすると見出しをドラッグして並べ替えできます。もう一度押すとその順序でロックします。横スクロール対応です。CSVの列順は固定です。

### devLibra連携とバリア合計

バリアの個別表示を廃止し、「バリア合計」列にdevLibraのBarrier HPタブの **Barrier** 値をそのまま保存・表示します。現在HPを加算したDisplay HPではありません。devLibraの計算処理は変更せず、その結果をIPCで共有しています。devLibra由来の回復量観測・割合計算による推定値であり、すべての場合に正確な残量を保証するものではありません。

1. AMTの `latest.zip` を導入します。バージョンは1.0.0.3です。
2. 別途 `devLibra-latest.zip` の連携対応版を導入して有効にします。devLibraは添付の1.0.0.1（dot-text-style-source）ベースで、同名の既存版と二重読み込みしないでください。今回の配布はローカル導入用で、GitHub公開版や別タスクの作業フォルダは更新していません。
3. AMTの **連携プラグイン** タブで「接続済み」を確認します。旧devLibraには値を渡すIPCがないため、起動していても未接続になります。
4. 通常のパーティリストを表示・更新できる状態にして、新しい戦闘を記録します。devLibra設定画面を開いておく必要はありません。「Add barriers to displayed HP」のチェックもデータ連携には不要です。

接続していても、対象者のデータなし、500msを超えた古いデータ、最大HP不一致、通常／リプレイの不一致は「取得不可」にします。未接続時にAMT独自の計算値や0へ置き換えません。保存された値はdevLibra終了後も履歴に残ります。旧履歴には新しいバリア値を後付けしません。通常／リプレイとも、devLibraのパーティリスト側に対象が表示・更新されない場合は取得できません。

IPCは `devLibra.BarrierHP.Version` と `devLibra.BarrierHP.SnapshotV1` です。対象のEntityIdを使って照合するため、パーティ順の並べ替えで別人の値を割り当てません。計算元はバリア合計セルのツールチップ・CSVの「バリア情報」で確認できます。

### 敵ステータスと軽減%

敵ステータスは攻撃通知のcasterポインタからStatusManagerを直接読み、取得できなければオブジェクト一覧を参照します。攻撃判定の処理直前に保存します。敵DoT（Status説明で判定したID）とデスデザインは画面・CSVから除外し、味方のDoT表示・被ダメージ記録は維持します。取得に成功して効果が空の場合は「—」、本当に取得できない場合は「取得不可」です。古い履歴の未保存ステータスは復元できません。

**軽減%** は、バフ列に表示している各ステータスの軽減率の単純合計です。敵バフ・敵デバフ・味方デバフは加算しません。敵情報が取得不可でも計算できます。バリア専用ステータスは0%としてバリア合計列で扱います。100%を超えても上限処理しません。

- ランパート20% ＋ ホーリーシェルトロン15% ＋ ナイトの堅守15% ＝ **50%**。
- 軽減率はゲームの日本語 `ActionTransient.Description` にある「被ダメージを○%軽減」「被物理ダメージを○%軽減」「被魔法ダメージを○%軽減」から取得します。回復量アップ・最大HP・バリア量の百分率は加算しません。IDによる対応表はアビリティの特定だけに使い、軽減率の固定表は削除しました。
- ダークミッショナリーなども説明文の率に従います。例えば説明が物理5%・魔法10%なら、陣10%＋タクティシャン15%との合計は物理30%・魔法35%です。以前のユーザー指定固定率は使用しません。
- 子効果は「ナイトの堅守効果：…」など対応する説明部分だけを読みます。親アビリティと子効果を二重加算しません。付与元により率が異なる場合は、記録開始後に観測した付与通知のアビリティを優先します。付与元未観測・説明が曖昧な場合は率を推測せず「＋未設定」とします。
- 説明文の抽出元アビリティ名・ID・軽減文は、軽減%のツールチップとCSVの軽減情報に記録します。取得済み履歴には当時の説明由来の率を保存します。従来の履歴は起動時の説明で補完できる範囲のみ計算します。すでに出力したCSVは自動で書き換えません。
- 説明文は現在インストールされているゲームデータのものです。過去パッチのリプレイ当時の説明や、条件による追加率・レベル別補正まで推測する機能はありません。
- 攻撃種別が不明でも、物理・魔法で同率のバフは加算します。未設定・種別不明で率を決められないバフが混ざった場合は、判明分を「20%＋未設定」のように残し、ツールチップ・CSVに未設定の名称を出します。率を推測して補いません。

攻撃名称の先頭には物理は剣、魔法は杖のアイコンを描きます。ゲームのダメージ種別フラグで分類し、不明・混在の場合は推測でアイコンを付けません。アイコンはこのプラグインで描画するシンボルです。CSVには画像を埋め込みません。

### 列の表示・非表示

「列表示・非表示を変更」を押すと、ヘッダー上部に各列のチェックボックスが表示されます。チェックを外すと非表示、入れると再表示です。非表示の列もチェックボックス一覧から消えないので、すべて非表示にしても戻せます。設定は再起動後も保持します。「列変更：許可中」の列順ドラッグとは独立しています。表示変更はCSVの列や保存データを削除しません。

### 想定ダメージの計算

確認済みの指定式は **`元ダメージ × (1 ＋ 軽減% / 100) ＋ バリア合計`** です。

`10,000 × (1 + 20 / 100) + 2,000 = 14,000` と表示します。小数は切り上げます。devLibraのバリア合計を使用し、バリアがある場合も計算します。これはユーザー指定の評価式であり、ゲーム本来の乗算軽減を逆算した値や乱数を含む厳密な最大ダメージではありません。

軽減率がすべて判明し、バリア合計も取得できた場合に数値を表示します。devLibra未接続・旧履歴でバリアが未保存・未設定の軽減率がある場合は「算出不可」と理由を表示します。未取得バリアを0とみなしません。未設定の軽減が混ざる場合も「軽減%」欄の既知小計は残します。

HP更新のフックがゲーム更新で利用できなくても、既存のダメージ記録を継続し、画面にエラーを表示します。HP更新のフック、敵ステータス、赤色表示、列ドラッグは実ゲームでの確認が必要です。

## バフ・デバフ表示の更新（バージョン1.0.0.3を維持）

- バフとデバフを別列に分け、画面ではゲーム内のアイコンと名称を組み合わせて表示します。カテゴリー1をバフ、2をデバフとして扱います。
- 各欄は3件まで表示し、4件以上ある場合は2件と残り件数を表示します。アイコン・名称・残り件数へマウスを重ねると全件のアイコンと名称を確認できます。
- アイコン読み込み中・取得できない場合も名称は残します。取得できない情報や旧履歴の分類が曖昧な効果は内部に保持し、味方の軽減限定欄には混ぜません。
- カンパニーアクション判定フラグに加え、同じアイコンを使う同系統の強化効果も除外します。フラグのない食事効果時間延長（1084）、討伐経験値アップ（1080）なども対象です。食事（48）も除外します。
- 保存済み履歴は読み込み時に名称をゲームデータと照合し、除外・分類・アイコン補完を行います。再出力CSVにも適用します。既存CSVファイル自体は変更しません。
- CSVは下記の分析情報を含む18列です。CSVには画像を埋め込まず、それぞれ名称を保存します。
- 実時間計測、リプレイモード、ペット除外は引き続き有効です。実ゲーム内のアイコン描画は未検証です。

## 実時間計測への変更

リプレイで経過時間が00:00のままになる問題に対応し、両モードとも戦闘開始検出時からStopwatchの単調増加時計で実時間を計測します。画面の経過・攻撃行の時間・CSVの時間・合計戦闘時間は同じ時計を使用します。再生位置は位置移動検出と履歴の補助情報のみに使います。
リプレイを一時停止しても計測時間は進みます。倍速時も実際に経過した秒数を記録します。過去に00:00で保存された記録の時間は復元できません。

## リプレイモードと画面デザイン

- 画面上部の「取得モード」で「通常モード」「リプレイモード」を選択できます。選択は保存されます。通常モードはリプレイ中の通知を除外し、リプレイモードは通常プレイ中の通知を除外します。
- リプレイ用パーティ（ReplayGroup）から対象者を取得し、通常の攻撃と継続ダメージを記録します。ペット除外・AA表記・食事/カンパニーアクション除外も適用します。
- ネイビーの背景、ミント色のアクセント、ジョブ別の色、コンテンツ・経過・記録数のサマリー、右側の履歴リストに刷新しました。

### リプレイモードの使い方

1. `/amt` で画面を開き、取得モードから「リプレイモード」を選択します。
2. 「記録を有効にする」を押します（`/amt on` でも可）。
3. ゲーム側でコンテンツリプレイを再生します。画面は待機から記録へ切り替わります。
4. 戦闘終了・リプレイ終了・手動停止でCSVが確定します。履歴の `REPLAY` 表示で通常戦闘と区別できます。

リプレイの経過時間には、戦闘開始からの実時間を使用します。一時停止中も時間は進みますが、その間に届く状態復元通知は取得対象外です。戦闘状態の解除による終了判定は再生再開後に行います。
巻き戻し（50ms超）・通常の進行幅を超える前方移動（2秒の許容幅あり）は記録を区切り、移動先から新しい記録を作成します。小さな位置移動や、再生位置に反映されない移動は検出できない場合があります。
モードを変更すると現在の記録を確定します。飛ばした区間・有効化以前の区間を自動で再生して埋める機能はありません。全体取得時は戦闘前から連続再生してください。
CSV名の開始日時は今回の取得開始日時です。終了日時はそこに実経過時間を加えます。元の収録日の日時ではありません。履歴JSONにはモードと取得開始時の再生位置も保存します。CSVは分析情報を含む18列です。

実機で、等速と倍速の同一戦闘の時間・行数、一時停止前後、巻き戻し、チャプター移動、再生終了、モード変更、8人全員の取得を確認してください。再生シーク中のゲーム内部の復元動作も含め、現段階では実機検証未完了です。

## ペットアクションの除外

- ペット・バディ（チョコボ等）のアクションを、攻撃・回復・バフ・対象なし通知も含め、記録対象から除外します。
- ペット種別、または自分・パーティメンバーの所有者IDで識別します。オブジェクトテーブルで取得できない場合も通知元のネイティブ情報で判定します。
- 敵の補助オブジェクトや所有者不明の通常攻撃は除外しません。
- この変更は新しく受信するアクションに適用します。保存済み履歴には当時の所有者情報がないため、自動削除しません。

## 1.0.0.2の修正

- 攻撃元を特定の敵NPC種別に限定していた条件を撤廃しました。補助オブジェクト、攻撃元不明、プレイヤー自身や他のパーティメンバーから届く効果も、実際の被ダメージ対象が自分・パーティなら記録します。
- アクション効果の適用先フラグを解釈し、プレイヤーへ返る反射・反撃も記録します。敵への与ダメージ・回復は加算しません。
- ActorControlの継続ダメージ通知（0x605）を追加監視します。DoTや、この通知経路で送られる床ダメージを記録します。
- DoTの発生元を特定できない場合も数値を残し、敵名は `不明（継続ダメージ）` とします。合算通知は `継続ダメージ（合算）` と表示し、推測で敵や技に分配しません。
- 履歴JSONに攻撃ID・攻撃元ID・シーケンス・取得経路を保存します。CSVは現在、分析情報を含む18列です。
- アースシェイカー相当の模擬データで複数対象・10万ダメージ・CSV出力を検証しました。実ゲームでの再現確認は未実施です。既に記録から欠落した過去のダメージは復元できません。

## 導入

1. `latest.zip` を任意の固定フォルダに展開します。DLL、JSON、imagesフォルダを同じ階層に保持してください。
2. Dalamudの設定の「開発者向け」から、開発プラグインの読み込み先に展開した `AutoMakeTimeline.dll` のフルパスを登録します。
3. プラグインインストーラーの開発プラグインから Auto Make Timeline を有効にします。
4. `/amt` で画面を開き、`/amt on` で監視を開始します。初期状態は停止です。

画面の項目名はDalamudの表示言語・バージョンにより異なる場合があります。
ZIPをカスタムプラグインリポジトリURLとして登録することはできません。

## コマンド

| コマンド | 動作 |
| --- | --- |
| `/amt` | メイン画面を開く |
| `/amt on` | 自動作成を有効にし、戦闘開始を待つ |
| `/amt off` | 現在の戦闘を確定して監視停止 |

起動状態と出力フォルダは保存します。戦闘の途中から有効にした場合、開始以前の攻撃は復元できません。

## 記録と戦闘区切り

- 自分、または読み取り可能なパーティメンバーの戦闘状態で開始します。先に被攻撃結果が届いた場合は、その受信時刻で開始します。
- 攻撃結果受信時刻から、単調増加クロックで経過時間を計算します。PCの時刻補正の影響を避けます。
- 戦闘状態が解除されて1.5秒経過したら終了を確定します。終了時刻には解除時点を使用します。開始直後に戦闘状態を観測できなかった場合は5秒待ちます。
- 全滅、コンテンツクリア、エリア移動、ログアウト、手動停止、プラグイン終了でも記録を確定します。
- ソロでは自分を記録対象にします。通常パーティは自分を含む最大8人です。アライアンス全24人、ペット、フェイスNPCは被ダメージ対象に含めません。
- PvPは記録対象外です。
- 攻撃Noは戦闘ごとに1から始まります。同じ攻撃元・サーバーシーケンス・アクションIDを持つ通知は同じNoと時刻にまとめます。対象者ごとに1行です。
- サーバーシーケンスが0の場合、別の攻撃を誤って統合しないよう受信通知単位でNoを付けます。

## 取得範囲と制約

ダメージ取得は `ActionEffectHandler.Receive` と `PacketDispatcher.HandleActorControlPacket`、残りHP取得はEffectResult／EffectResultBasicを監視します。以下の取得経路を拡張しましたが、実機確認前のため全ダメージの完全取得は保証できません。

記録できるもの:

- アクション結果通知に含まれる、自分・パーティへの被ダメージ。オートアタック、詠唱完了後の攻撃、無詠唱攻撃、補助オブジェクトからの攻撃など。攻撃元の名称を取得できなくても数値を記録します。
- オートアタックはActionCategory=1（ID 7も補助判定）で識別し、画面・CSVともに `攻撃（AA)` と表示します。敵固有IDのオートアタックにも対応します。保存済み履歴もゲームデータの名称と照合し、表示・再出力時に補正します。既存CSVファイルは自動変更しません。
- 通常・ブロック・受け流しダメージ。16bitを超える拡張値にも対応します。
- ミス・レジスト・無敵は0ダメージ。反射・反撃は実際の適用先が自分・パーティの場合に加算し、元の攻撃名に `（反射・反撃等）` を付記します。
- ActorControl 0x605の継続ダメージ。HoT（回復）通知は除外します。複数通知を同一攻撃と誤認しないよう、DoTは受信通知ごとにNoを付けます。
- 敵の結果通知にパーティ対象がない場合も、戦闘中は敵名称と攻撃名称を残します。

取得しない／保証できないもの:

- 上記2経路のどちらにもダメージ値が通知されない床・環境ダメージ、HP直接設定型のギミック。HP差分を被ダメージとみなす推計はしません。
- クライアントに読み込まれていない攻撃元、通知が届かない遠方の攻撃。
- 詠唱開始と中断の別イベント。記録する時刻は攻撃結果の受信時刻で、詠唱開始時刻ではありません。
- 攻撃ごとのバリア吸収量や、個々のバフが軽減した量。

ダメージは受信したアクション効果値であり、前後のHP差分から推計しません。
取得対象外・数値なしはCSVで空欄、画面で `—` とし、実測0と区別します。
バフ・デバフは**攻撃結果のゲーム内処理直前**のスナップショットです。
その攻撃で新しく付与されるデバフがまだ含まれない場合や、サーバー側の判定時点とずれる場合があります。
カンパニーアクション（Status.IsFcBuff）と食事（Status ID 48）は除外します。保存済み履歴も名称照合で表示・再出力時に除外します。内部のスナップショットには他の戦闘ステータスも残しますが、味方バフ欄・CSVには軽減・バリアだけを表示します。ステータスの残秒、スタック数、付与元はCSVに含めず、名称を列挙します。
名前はゲームクライアントのデータ言語に従います。日本語名が必要な場合は日本語クライアントを使用してください。

DoTはゲーム側で複数の継続ダメージが合算される場合があり、全てを正確な敵名・攻撃名へ分解できるとは限りません。数値は通知された合計を記録します。
参考: [cactbotのNetworkDoT仕様](https://github.com/OverlayPlugin/cactbot/blob/main/docs/LogGuide.md#line-24-0x18-networkdot)

## CSV

WindowsのKnown Folder APIで取得した標準「ダウンロード」が初期出力先です。
フォルダを移動している場合もWindows設定に従います。「出力先設定」で変更できます。

戦闘開始時に `コンテンツ名称_開始日時_記録中_AMTLOG.csv` を作成し、攻撃結果を逐次書き込みます。
戦闘終了時に、確定HPと同一No.内のダメージ降順を反映してCSVを再構成し、以下の名前に変更します。記録中のCSVは受信順の速報で、HPが未確定の場合があります。終了直後に対応するHP更新が届いた場合は、自動保存CSVと履歴を更新します。

```text
コンテンツ名称_20260908-210000-123_20260908-210530-456_00h05m30s_AMTLOG.csv
```

開始・終了日時はローカル時刻、ミリ秒付きです。Windowsの禁止文字は `_` に置換します。
同名ファイルが存在する場合は末尾に連番を追加して上書きを避けます。

```csv
No,時間,エネミー名称,攻撃名称,被ダメージ,被ダメージ対象のジョブ,バフ情報,デバフ情報,エネミーバフ情報,エネミーデバフ情報,残りHP,致死,バリア合計,想定ダメージ,算出情報,軽減%,軽減情報,バリア情報
"1","00:10","敵","攻撃（AA)","800","DRK","ランパート","","","","4200","","0","960","800 × (1 + 20 / 100) + 0","20%","ランパート: 20%","devLibra / Party-list shield percentage"
```

- UTF-8 BOM付き、CRLF改行。全データ欄をダブルクォートで囲みます。
- 時間は `分:秒`。1時間を超える場合も `61:01` のように分が増えます。
- セルのカンマ・引用符・改行を適切にエスケープします。
- 表計算で数式として解釈されうる文字列の先頭には安全化用の `'` を追加します。
- 書き込み失敗時は画面にエラーを表示し、可能な限り内部記録を続けます。
- 異常終了した場合、既に書き込まれた「記録中」CSVは残りますが、終了日時への変更と履歴確定は行われません。OS障害時の完全な永続性は保証しません。
- 通常の戦闘終了ではCSVを自動保存します。「結果をCSVで出力」は選択した終了済み履歴をもう1つ保存する機能です。

## 履歴・画面

完了した最新100戦をDalamudのプラグイン設定ディレクトリの `history` にJSONで保存します。
101戦目で最古の内部履歴を削除します。ダウンロード先のCSVは自動削除しません。
保存済み履歴はプラグイン再起動後も選択・再出力できます。
記録中の1戦は完了済み100戦とは別枠です。

ネイビーのダークテーマにミント色のアクセントを採用しています。画面上部にモードと取得状態、中央に攻撃一覧、右側に履歴、下部にCSV出力を配置しています。
同一攻撃のNo・時間・敵名・攻撃名はグループ先頭だけに表示します。
ImGuiの表ではセル自体を縦結合しておらず、見本と完全なピクセル一致ではありません。
列幅は変更でき、長い内容はマウスを重ねると全文を確認できます。
大きな戦闘記録は可視行だけ描画します。
アイコンは `images/icon.png` に設定しています。

## ソースからビルド

必要環境: Windows x64、.NET SDK 10、Dalamud API15の開発用DLL。

```powershell
dotnet build ./AutoMakeTimeline/AutoMakeTimeline.csproj -c Release
dotnet run --project ./Tests/Tests.csproj -c Release
pwsh -File ./build.ps1
```

Dalamud.NET.Sdk 15.0.0が標準のDalamudインストール場所を参照します。
別配置のライブラリはSDKがサポートする `DalamudLibPath` を指定します。
`source.zip` は今回更新したAMTのみを収録します。`AutoMakeTimeline/build.ps1` はAMTのみをビルド・検証し、`artifacts/latest.zip` と `artifacts/source.zip` を作成します。devLibraは既存の連携対応版をそのまま使用してください。
DalamudやFFXIVClientStructs等のホスト提供DLLは配布ZIPに同梱しません。

## 正式配布前の実機確認

未実施の項目です。実戦環境で確認してください。

1. API15でロード・アンロードが成功し、`/amt` とアイコンが表示される。
2. ソロの通常攻撃、8人への全体攻撃、複数ヒットで、ゲームの表示と数値・対象・Noを比較する。
3. 10万以上の被ダメージ、ブロック・無敵で数値を比較する。
4. 攻撃直前のステータス付与・消失時に、スナップショットを比較する。
5. 全滅・再挑戦・クリア・エリア移動・ログアウト・`/amt off` で戦闘が区切られる。
6. 再起動後の履歴とCSV再出力、出力先の書き込み拒否、長時間戦闘を確認する。
7. ゲーム更新後、フックが解決するだけでなく実際に正しい攻撃結果を取得できることを確認する。
8. 真成4のアースシェイカー・床の継続ダメージで、実際の被ダメージと記録値を比較する。反射・反撃が自分と敵のどちらに加算されるか確認する。
